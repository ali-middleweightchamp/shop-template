# CLAUDE.md

Этот файл читается автоматически при каждом запуске. Здесь — постоянный контекст проекта.

## Что мы строим

Переиспользуемый **шаблон интернет-каталога** для малого бизнеса Узбекистана (канцтовары, автозапчасти, стройматериалы, оптовики).

Продуктовая идея: у магазина нет времени осваивать новые системы.

- **Покупатель** без регистрации собирает корзину и жмёт «Заказать».
- Открывается **Telegram продавца с готовым текстом заказа** (товары, количество, сумма). Остаётся нажать «отправить».
- **Продавец** ничего не осваивает: заказы приходят в обычную личку. Товарами управляет через Django Admin, прайс загружает файлом Excel.

Шаблон должен разворачиваться под нового клиента за пару часов: изменил настройки в админке (название, логотип, цвет, telegram, телефон), загрузил прайс — сайт готов. **Ничего специфичного для конкретного магазина не хардкодить.**

## Стек

Строго этот, без замен на аналоги:

- Python 3.12, Django 5.x, PostgreSQL 16
- Django Templates + Tailwind CSS (CLI-сборка) + Alpine.js
- Pillow, easy-thumbnails, openpyxl, django-environ
- gunicorn, whitenoise
- Docker + docker-compose (web, db, nginx)
- ruff + black

Никакого DRF, React, Vue, Next, Celery, Redis, Elasticsearch.

## Правила разработки

- Mobile-first. 90% посетителей приходят по ссылке из Instagram с телефона.
- Никаких хардкодов названия, цветов, контактов — всё из модели `ShopSettings` через context processor `shop`.
- Страницы должны быть лёгкими и быстро открываться на слабом мобильном интернете.
- Комментарии в нетривиальных местах — на русском.
- Двуязычность ru/uz (латиница) через стандартный i18n Django.
- После каждого этапа проект должен запускаться и работать. Ломать рабочее состояние нельзя.
- Коммить после каждого завершённого этапа, сообщение на русском.

## Чего НЕ делать

Не добавляй, даже если кажется полезным:

- регистрацию и личный кабинет покупателя
- онлайн-оплату (Payme, Click, Stripe)
- отзывы, рейтинги, вишлисты, сравнение товаров
- фильтры по характеристикам и цене (**исключение:** фильтр по бренду — разрешён,
  бренд берётся из характеристики товара «Бренд/Brand/Марка»)
- SPA-фронтенд
- складской учёт, приход-расход, интеграцию с 1С
- микросервисы, очереди, поиск на Elasticsearch

Это либо не нужно в первой версии, либо будет платным вторым этапом.

## Ключевые технические решения

**Корзина** — только `localStorage`, ключ `cart_v1`, структура `{sku: {name, price, qty, unit}}`. Обязана переживать перезагрузку и закрытие вкладки.

**Кнопка заказа** — deep link:

```js
window.location.href = `https://t.me/${shop.telegramUsername}?text=${encodeURIComponent(text)}`;
```

Аналогично WhatsApp: `https://wa.me/${phone}?text=...`

Если закодированный текст длиннее ~1500 символов — отправляем сокращённый вариант (первые 10 позиций + «…и ещё N») с коротким кодом заказа и ссылкой на `/order/<code>/`, где лежит полный состав (модель `ShortOrder`).

**Импорт Excel** — ключ сопоставления `sku`. Устойчивость к кривым файлам обязательна: цены вида `"12 500 сум"`, наличие в виде `да/нет`, `+/-`, `1/0`, `bor/yo'q`, заголовки в любом регистре, битые строки не роняют импорт а попадают в отчёт с номером строки.
